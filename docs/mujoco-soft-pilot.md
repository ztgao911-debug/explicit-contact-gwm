# 第一批独立 MuJoCo 软体试采

日期：2026-10-13（Asia/Shanghai）。当前 Mac 上已实际完成七条轨迹的试采。
环境为 Apple M1 / arm64、macOS 15.6.1、Python 3.13.5、MuJoCo 3.3.7。
使用原生 CPU 求解器，绘图由 Matplotlib 3.11.2 完成，无需 GUI 或 GPU。
原有两份验证记录、Toy 配置和核心模型实现保留。

## 场景、目的和预期

本批先建立固定底部的三维软块，为局部形变监督提供独立仿真标签。
软块的静止尺寸为 60 × 40 × 30 mm，共 140 个节点、432 个四面体、216 个表面三角形。
底部 35 个节点固定到世界坐标系，其余节点具有三维平移自由度。
球形压头半径 12 mm、质量 0.05 kg，以三个位置伺服器驱动；位置及速度由求解器计算，
保存时同时记录目标位置、目标速度和实际状态。

MuJoCo 的原生 `flex/elasticity` 使用三维 Saint Venant–Kirchhoff 有限元弹性模型；
Young 模量 5000 Pa、Poisson 比 0.3、Rayleigh 阻尼系数 0.0002 s。
见 [MuJoCo 3.3.7 弹性参数文档](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#flex-elasticity)。
`flexcomp` 的名义总质量设为 0.072 kg，分配到 140 个节点；固定节点挂到世界，
实际活动节点质量合计为 0.054 kg，具体值保存在 `mesh.npz/node_masses`。
地面几何仅用于显示，底部固定约束提供支撑；重力为零，以单独观察按压与恢复。

这批数据的形变、速度、接触几何和接触力来自 MuJoCo，未调用项目的
Gaussian 接触解析、接触力公式或未训练网络产生仿真标签。
派生形变指标是求解器节点位置减去保存的初始节点位置。

按压位置 x 为 −20 / 0 / +20 mm，y 为 0；浅、深按压的目标下压量分别为 3、6 mm，
以球体和 flex 碰撞外壳刚好接触的高度为零点。实际形变不强制等于目标深度，
因为求解器包含接触柔顺性、动态响应和控制器跟踪误差。
无接触对照也执行五段动作，但球心始终足够高，最低目标为 55 mm。

| 阶段 | 时间范围（s） | 目的 |
| --- | --- | --- |
| 接近 | 0–0.4 | 从远处接近物体上表面 |
| 按压 | 0.4–1.0 | 平滑降低压头目标位置 |
| 保持 | 1.0–1.4 | 观察持续接触下的形变 |
| 释放 | 1.4–2.0 | 平滑撤回压头 |
| 恢复观察 | 2.0–3.0 | 观察无接触后的弹性恢复 |

移动段使用余弦插值，目标速度在段边界为零。
物理步长 0.0002 s（5 kHz），保存间隔 0.01 s（100 Hz），每条轨迹 301 帧，
包括 t=0 和 t=3 的状态。随机种子记录为 7，但当前协议没有随机化。

## 七条轨迹的实测结果

| 轨迹 | 峰值节点位移（mm） | 最终残余（mm） | 最大向下接触合力（N） | 采集耗时（s） |
| --- | --- | --- | --- | --- |
| left_shallow | 3.241 | 0.049 | 0.152 | 2.00 |
| left_deep | 6.865 | 0.081 | 0.269 | 1.98 |
| center_shallow | 3.362 | 0.057 | 0.170 | 1.98 |
| center_deep | 7.183 | 0.134 | 0.311 | 2.00 |
| right_shallow | 3.345 | 0.155 | 0.145 | 2.03 |
| right_deep | 7.088 | 0.249 | 0.261 | 2.01 |
| no_contact | < 1e−10 | < 1e−10 | 0 | 1.87 |

六条按压均产生了非零局部形变，最大形变节点的初始坐标分别为
`[−0.02, 0, 0.03]`、`[0, 0, 0.03]`、`[+0.02, 0, 0.03]`，随按压位置迁移。
峰值时近接触区的顶部节点 RMS 位移高于远区：近区约 1.32–3.42 mm，
远区约 0.08–0.43 mm，显示形变主要集中在接触邻域。
浅、深按压的形变和力幅值有清楚区别。

底部节点位置误差实测为 0，速度为 0；最终均已失去接触。
恢复观察结束时残余为峰值的约 1.2%–4.6%，仍存在小幅振荡，没有声称完全恢复。
各帧四面体体积比最低约 0.605，未出现反转或塌陷；七条正式试采均无求解器警告。
无接触对照没有接触，最大节点位移约 1.51e−17 m，属于浮点误差量级。
左右结果存在差异，本批未强制镜像一致，也未校准网格离散和真实材料参数。

## 速度与容量

- 7 条轨迹，共 **2107 帧**、**105000 个物理积分步**、**21 秒仿真时间**。
- 纯 `mj_step` 的实测速率约 **10358–11381 步/秒**。
- 采集循环合计约 **13.87 秒**，包括状态读取、节点速度计算和采样检查，
  不含 NPZ 压缩写盘、重载和绘图；相当于约 **1.51 倍实时速度**。
- 7 个压缩轨迹 NPZ 共 **35304979 字节，约 35.30 MB**；未压缩数组约 58.26 MB。
- 加上网格、配置、代码快照、检查报告、两张调试图和缓存，目录约 **36.52 MB**。
- 模型编译约 0.01 秒；整批独立重载 / 重放检查约 0.46 秒；首次绘图约 11.44 秒，
  包含 Matplotlib 初次字体缓存构建。这些耗时与仿真循环分别记录。

时间与字节数来自本次运行的 `manifest.json` 和文件统计，其他机器或后续运行可能不同。

## 失败与参数探测记录

正式七条试采失败数为 **0**。在此之前，有 **1 次参数探测被拒绝**：
`dt=0.0005`、Young=10000 Pa、Rayleigh 阻尼=0.002 s 时，
MuJoCo 于 t=0.0315 s 报告 DOF 111 的加速度出现 NaN/Inf 或异常大值。
该次探测出现求解器自动重置和巨大位移，没有作为训练轨迹保存。

随后将材料和阻尼调整为当前配置，分别用 `dt=0.0001` 和 `0.0002` 探测中央深按压。
两次均无警告，峰值位移分别为 7.182875 和 7.182872 mm，最终残余分别为
0.133686 和 0.134395 mm。最后选用 0.0002 s 完成七条试采。
首次调整同时改变了材料参数和时间步，因此不能归因于单一因素；后两次才是同参数时间步比较。

原始警告保存在 `parameter_probe_MUJOCO_LOG.TXT`，数值探测记录保存在
`parameter_probe_history.json`。这些文件是调参审计记录，没有加入七条数据轨迹。
采集器逐积分步检查时钟、有限数值和警告；出现求解器重置或不稳定时拒绝接受轨迹。

## 保存格式与时间对齐

数据目录：`data/mujoco_soft_pilot/pilot_001/`，由 `.gitignore` 忽略。
`.gitignore` 的数据忽略规则限定在仓库根目录，确保 `src/contact_gwm/data/` 的采集代码可被跟踪。

| 文件 | 内容 |
| --- | --- |
| `mesh.npz` | 稳定节点 ID、初始世界坐标、固定掩码、节点体 ID 与质量、四面体、表面三角形、边、初始有符号体积 |
| 七个 `<case>.npz` | 每帧节点 / 压头状态、动作、求解器状态和变长接触标签 |
| `scene.xml` / `compiled_scene.xml` | 原始场景和包含展开后默认值的编译场景 |
| `config.yaml` | 完整材料、几何、求解器、时间、控制及验收配置 |
| `environment.json` | 平台、解释器、包版本、采集时间、Git 版本与工作区状态 |
| `collector_backend.py` / `collector_entrypoint.py` | 本次运行代码的原始快照，用于溯源 |
| `manifest.json` | 七条轨迹描述、SHA-256、配置、容量、速度、验证结果和失败列表 |
| `reload_validation.json` | 整批重载与独立求解器重放结果 |
| `metrics.csv` | 七条轨迹指标表 |
| `deformation_curves.png` | 形变与接触合力曲线 |
| `center_deep_shape.png` | 初始形状与中央深按压的最大形变快照 |

NPZ 使用 `allow_pickle=False` 加载，节点编号在所有帧和所有轨迹中一致。
以下 F 是帧数（301），N 是节点数（140），C 是所有帧接触条目总数。

| 轨迹数组 | 形状 / 含义 |
| --- | --- |
| `node_ids` | `[N]`，对应共享网格 |
| `time`, `step_index`, `phase_id` | `[F]`，秒、积分步索引、五段协议 ID |
| `node_position_world`, `node_velocity_world` | `[F,N,3]`，m、m/s |
| `indenter_position_world`, `indenter_velocity_world` | `[F,3]`，实际求解器状态 |
| `indenter_quaternion_wxyz` | `[F,4]`，wxyz；本例球体只有平移自由度 |
| `action_target_position`, `action_target_velocity` | `[F,3]`，位置伺服目标与目标函数的时间导数 |
| `actuator_force` | `[F,3]`，三轴伺服器的实际力 |
| `qpos`, `qvel` | 每帧广义状态 |
| `integration_state` | 每帧 `mjSTATE_INTEGRATION` 状态，用于还原求解器状态 |
| `solver_iterations` | 每帧 MuJoCo 各约束岛的迭代计数 |
| `contact_count`, `contact_offsets` | `[F]` 和 `[F+1]`，接触数量及变长条目的索引 |
| `net_contact_force_on_block_world` | `[F,3]`，作用于软块的接触合力，N |
| `contact_position_world`, `contact_frame_world` | `[C,3]` 和 `[C,9]`，点与世界坐标接触基 |
| `contact_signed_distance` | `[C,1]`，求解器的有符号距离，m |
| `contact_wrench_local` | `[C,6]`，MuJoCo 原始接触坐标系力 / 力矩 |
| `contact_force_on_block_world` | `[C,3]`，根据接触侧和接触基转换的软块世界坐标受力 |
| `contact_geom_ids`, `contact_flex_ids` | `[C,2]`，接触两侧的求解器对象 ID |
| `contact_element_ids`, `contact_vertex_ids` | `[C,2]`，四面体 / 节点关联；−1 表示不适用 |
| `contact_efc_address`, `contact_dimension` | `[C,1]`，约束索引与接触维数 |

节点 ID 按编译后的 flex 顶点顺序定义，拓扑索引均引用这些节点 ID。
接触条目随每帧变化，没有将接触 ID 当作跨帧稳定实体。
接触基按行储存世界坐标轴，首行为 side0 指向 side1 的法向；
MuJoCo 原始接触力作用于 side1，若软块位于 side0，转换后受力取反。
约定参考 [MuJoCo 接触方向文档](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#contact-pair)。

所有帧字段对应同一个 `time[k]`。采样前设置该时刻动作，并执行 `mj_forward`，
同步几何、速度与接触力；随后才向下一个积分步推进。
节点速度由 MuJoCo 节点位置 Jacobian 乘求解器 `qvel` 得到，压头速度也如此。
目标速度仅描述动作轨迹，不能替代实际压头速度。
接触标签按 100 Hz 保存，未声称记录了全部 5 kHz 子步中的瞬时接触事件。

## 保存后检查与复现

保存后逐数组重载，确认与保存前数据完全相同；进一步核对 SHA-256、节点编号、
网格拓扑、时钟、动作、五段协议、底部固定、接触打包、合力及四面体体积。
每条重放初始帧、峰值帧和最终帧，共 21 个选定状态，使用 MuJoCo 状态恢复后重新计算
节点位置、速度和接触合力。本次这些重放误差均为 0。
这验证了保存标签与独立求解器的一致性，不等于真实材料准确性验证。

当前环境已安装所需依赖。重新加载检查已有数据：

```bash
source .venv/bin/activate
python scripts/collect_soft_pilot.py --validate-only data/mujoco_soft_pilot/pilot_001
python -m pytest
```

重新试采时保留当前七条数据，指定新目录：

```bash
python scripts/collect_soft_pilot.py --output-dir data/mujoco_soft_pilot/pilot_002
```

新环境安装可选依赖：

```bash
python -m pip install -e ".[dev,simulation]"
```

本机联网安装沿用首次验证的 CA 证书路径；必要时在 pip 命令中加入
`--cert /opt/anaconda3/ssl/cert.pem`。其他机器使用自己的有效证书配置。
MuJoCo 被固定为 3.3.7，以减少本批格式和物理行为的版本变化。

原有 7 个测试全部通过；新增 3 个可选 MuJoCo 测试检查拓扑与固定层、保存重载与重放、
错误时间和伪造节点标签的拒绝行为，本次总计 **10 passed in 1.67s**。
没有安装 MuJoCo 的基础环境会跳过这三个可选测试。
独立命令 `--validate-only` 实际重载七条数据并通过重放。
原 Toy 再次运行，仍检测到 1 个接触、向下合力和位移，局部形变为零；
原合成实验的 23/23 项检查也再次通过，与之前记录一致。

## 本批的适用范围

已获得独立软体求解器的节点形变监督，可作为后续小规模训练的数据输入。
当前是固定底部、单材料、单压头的小网格试采，包含六条干预和一个对照；
未采 RGB-D，也未把节点自动转换为 Gaussian，尚未执行训练。
正式训练前仍需定义节点与 Gaussian 的对应关系、监督目标和按完整轨迹划分的数据集。
当前网格和材料参数用于可运行性验证，后续需要网格 / 时间步收敛、材料校准及更多场景验证。
