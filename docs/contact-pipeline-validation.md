# 固定边界接触管线与短时软体预测

2026-10-26，已在当前 Apple M1 / macOS / CPU **实际执行**。最终结果目录：
`outputs/contact_pipeline_validation/run_003/`。

管线已连通，但预测精度没有通过恒速对照。当前优先瓶颈是**局部状态转移缺少无接触时的弹性恢复**，
还有原训练接触筛选口径与部署几何候选不一致的问题。高斯几何漏检、解析力误差也已测得，
不能因为高斯组某些位置误差较低，就宣称几何更准确。本轮没有训练新网络，没有扩大数据。

## 做了什么，以及每步的目的

1. 读取已有网格、轨迹和空间编码 B 权重，检查文件摘要、节点编号和记录时间间隔，确保数据来源一致。
2. 从当前高斯中心和瞬时速度重建 MuJoCo 的 slide 自由度，只查询当前接触，避免 rollout 回放软体真值。
3. 仅用中央训练轨迹标定解析力系数，再冻结系数，在左侧验证轨迹上比较三种条件。
4. 硬约束底部节点，明确位移与瞬时速度的离散关系，运行单步及 5 / 10 / 20 步预测。
5. 保存并重载模型与预测数组，生成曲线，运行全部测试和 Ruff，检查旧数据与结果未变。

新增入口 `scripts/validate_contact_pipeline.py`，配置 `configs/validate_contact_pipeline.yaml`，
实现 `src/contact_gwm/pinned_contact_pipeline.py`。原 `world_model.py`、训练实现、权重及历史结果均保留。

## 固定实验协议

| 条件 / 方法名 | 当前接触几何 | 当前接触力 | 软体状态更新 |
| --- | --- | --- | --- |
| M / `mujoco_force` | MuJoCo 原生查询 | MuJoCo 原生约束求解 | 公共冻结网络 + 固定边界 |
| F / `analytic_force` | 同一 MuJoCo 几何查询 | 解析力 | 同上 |
| G / `gaussian_geometry` | 高斯解析几何 | 同一解析力与系数 | 同上 |
| CV / `constant_velocity` | 不需要 | 不需要 | 当前瞬时速度恒速外推 + 固定边界 |

使用空间编码消融 B 的既有检查点，**24326 参数，种子 7，先前只训练了固定中央 8 帧对**。
三组网络权重逐项相同，保留原归一化、sigma=0.02 m、单轴残差输出上限 0.001 m、固定尺度与旋转。
本轮参数更新次数为零，没有依据左侧结果挑选网络、几何尺度或力系数。

加载中央浅 / 深、左侧浅 / 深和 `no_contact` 共五条数组；右侧数组不加载、不评价、不调参。
为保护数据而计算的文件 SHA256 包括右侧文件，但不读取其数组用于实验。
每条 301 个状态，全部 300 对相邻帧参加单步评价，共 **1500 对 / 方法**。
当前阶段决定分组，包括接近、按压、保持、释放、恢复；不要求接触，不过滤阶段交界帧。
这与历史“仅有力的按压 / 保持帧对”口径不同，不能直接比较总分。

每个节点对应一个 Gaussian，稳定编号 0–139，其中活动节点 105 个、底部固定节点 35 个。
尺度固定为静止最近邻间距的一半（本网格 0.005 m），旋转为单位四元数。
G 使用网格边界节点的高斯；表面倍数固定为 0.2，使球形等值面半径为 0.001 m，
与已知 MuJoCo flex 碰撞皮肤厚度一致。压头高斯等值面半径为 0.012 m。
**这些稀疏节点球没有填满三角形面**，不能把皮肤半径一致解释为表面几何等价；未搜索其他半径。

评价均为三维向量 RMSE：`sqrt(sum(||error_i||²) / node_count)`，位置 / 增量单位 μm。
同一帧的三组及 CV 共用掩码，先汇总误差平方与节点数，再开根号。
活动区域为所有非固定节点；接触邻域为真实当前受力接触点 0.02 m 内的活动节点。
脱离接触时沿用最后的参考邻域；首次接触前，以压头下方的静止顶面点定义同半径邻域。
rollout 固定使用初始化帧的邻域。**这些真值掩码仅用于评分，不进入前向计算**。
每种方法各组节点数一致的检查已通过。

## 力、坐标与单位核对

全部几何量和状态使用世界坐标。MuJoCo 接触局部坐标第一轴为法向，
`mj_contactForce` 返回接触坐标中的力矩；本场景 condim=3，没有独立接触偶矩。
转换为软体所受力：`F_world = side_sign * frame.T @ wrench[:3]`，
软体是接触 side 1 时 sign=+1，否则 -1。法向也按同一符号转为“压头 → 软体”。
MuJoCo 的符号与坐标定义见[接触计算说明](https://mujoco.readthedocs.io/en/3.3.7/computation/index.html#contact)，
局部力接口见[官方 API](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html#mj-contactforce)。

- 间隙、穿透、位置：m；速度：m/s；合力：N；力矩：N·m。
- 相对速度为 `v_indenter - v_soft_contact`，与法向点积为正表示接近。
- MuJoCo 面 / 单元接触的软体速度用当前四面体节点速度插值：接触中点重心坐标截为非负并归一化。
  这是碰撞皮肤处速度的近似，未宣称等于 MuJoCo 内部接触 Jacobian 插值。
  G 的接触点对应固定旋转、无自旋的节点球，速度为对应节点速度。
- 法向力为 `k*penetration + c*max(relative_velocity·normal,0)`，仅在 gap≤0 时生效。
  切向力沿相对滑动方向，大小 `min(4*|v_t|,0.3*|F_n|)`。离开方向不施加负阻尼拉力。
- 力矩统一为 `cross(contact_point - current_dynamic_COM, force)`，质心使用实际节点动态质量。
  **只作为诊断，不将其用于整个固定软块的自由平移或旋转**。固定边界的支撑反力没有显式预测。

M 调用 `mj_forward` 求当前力，不执行 `mj_step`，不使用原轨迹 integration state / warmstart。
F 仅调用 `mj_fwdPosition`，不执行原生力求解或 `mj_contactForce`；G 不查询 MuJoCo。
这些 API 的计算边界见[官方说明](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html#mj-fwdposition)。
测试会将原生力接口替换为抛错函数，F、G 仍可前向运行。

两组 MuJoCo 条件保留完全相同的 gap≤0 几何候选，包括法向力为零的候选，
不借助真实力筛选 F 的输入。检测标签仅在评分器中使用当前保存的非零受力接触。
本批数据中，M 的合力与保存标签在左侧 600 帧上 RMSE 为 **1.815e-16 N**，
确认坐标转换和重建查询可复现；最小 `F·normal` 为 0，质心力矩恒等式最大误差为 0。

标定只使用中央按压 / 保持的 **542 个几何接触候选**，对当前原生法向力做二变量非负最小二乘，
得到 `k=691.386733 N/m`、`c=0 N·s/m`；切向阻尼 4 N·s/m、摩擦系数 0.3 固定。
逐接触标定法向力 RMSE 为 **0.0488304 N**。
杨氏模量 **5000 Pa 只作为原网络材料特征**，从未直接充当 N/m 单位的接触刚度。
`c=0` 是这一受限拟合问题的边界解，不代表材料没有阻尼，也不代表辨识了真实材料参数。

## 发现的接触输入口径差异

原训练加载器会用真实力阈值丢弃零力候选；新公共几何不能这样依赖真实力。
因此增加了一个**仅在原中央 8 帧上的兼容性诊断**，不增加主实验条件、不用于选模或调参。

| 原 8 帧，冻结同一 B | 活动 RMSE μm | 原公共接触邻域 RMSE μm |
| --- | ---: | ---: |
| 原加载器，按真实力过滤候选 | 2.68307 | 1.31849 |
| 新管线，公共几何候选 | 3.44786 | 2.96284 |
| CV | 3.47989 | 2.44970 |

原拟合成绩复现通过。例：center_deep 第 71 帧，原加载器保留 2 个受力接触，新几何查询有 6 个候选。
网络对候选接触做归一化加权，零力候选也改变力上下文和门控。
这证明至少一部分退化来自训练 / 部署接触聚合口径差异，不能全部算成网络容量或解析力问题。

## 固定边界与瞬时速度

没有调用旧自由刚体积分器，也没有使用“合力 / 整块质量”移动固定软块。
每步将固定节点中心设回静止位置、速度设为零、总增量设为零。
尺度、旋转、透明度不更新；输出仍为含中心和速度的 GaussianSet。

现有 B 只学了位移残差 `r=gate*network(current_state,current_contact,current_force)`。
本轮不增加速度头、不重新训练，采用统一的**帧间恒加速度近似**：

```text
dt = 0.01 s
a_hat = 2*r/dt²
x_next = x + v*dt + r
v_next = v + 2*r/dt
```

`delta/dt` 是区间平均速度，不用作下一时刻瞬时速度。CV 的 r=0，所以保持当前瞬时速度。
这一近似只是对已有位移预测的解释，**没有接受真实端点速度监督**。
作为评分诊断，代入真实相邻帧位移，仍得到 center_deep 释放阶段端点速度 RMSE **3.294 mm/s**，
left_deep 为 **3.533 mm/s**。这说明 10 ms 内的真实变化并不普遍满足恒加速度，
即使位移拟合更好也不能据此保证端点速度正确；诊断的未来位移从未进入任何前向或 rollout。

## 实测 5 / 10 / 20 步预测

本轮明确是**给定压头轨迹的软体预测**。外部输入为每个当前记录时刻压头的实际位置、瞬时速度，
以及当前命令位置、速度；不预测压头自身运动，也不声称闭环机器人控制结果。
初始化后，`rollout(initial_gaussians, external_robot_inputs, method)` 不接受软体轨迹数组，
每步仅使用上一步预测中心、预测速度。M / F 从该预测状态重算接触；G 从预测高斯计算接触。
不存在真值软体位置、速度、接触或力回填。

预先固定起点帧为 **70、110、140、150、170、210**，每条轨迹六个窗口，
覆盖按压、保持、卸载、脱离接触、恢复观察。五条轨迹共 **30 个窗口 / 方法**，
均运行完整 20 步，提取 5、10、20 步指标（0.05、0.10、0.20 s），共 2400 次自回归状态更新。
卸载和脱离接触窗口按同一规则计分，没有为改善分数剔除。

### 卸载与恢复失败的具体证据

left_deep 在第 150 帧开始的窗口跨越脱离接触；真实形变回落并振动，模型在短暂减小后出现外推漂移。
第 170、210 帧开始的两个窗口，真实及三组预测均没有接触，最大门控值均为零，
所以三组的全部后续状态与 CV 一致：

| left_deep 起点 | 真实起始 RMS 形变 μm | 20 步后真实 RMS 形变 μm | 三组 / CV 预测 RMS 形变 μm |
| --- | ---: | ---: | ---: |
| 170（脱离接触） | 54.650 | 42.400 | 1169.631 |
| 210（恢复观察） | 26.394 | 19.606 | 692.997 |

这里是相对静止形状的 RMS 形变，不是前面的位置预测 RMSE。
真实轨迹的恢复并非逐帧单调；振动期间仍有瞬时速度，门控关闭却无法产生恢复加速度，导致弹性运动被当成弹道外推。
该失败在 M 的真实几何和真实力条件下同样存在，因此换更好的接触检测或接触力仍不足以解决。

## 结论的边界与唯一优先项

**实测支持的判断**：

1. 高斯几何确有严重漏检（左侧召回 7.65%）；解析力也不准确（有接触帧合力误差 0.143 N）。
2. 在 M / F 相同几何、相同网络下，替换真实力没有导致主要的单步位置误差变化；
   真实几何 + 真实力仍差于 CV，接触精度不能单独解释总失败。
3. 训练 / 部署候选接触口径不一致已经造成可复现的拟合退化。
4. 无接触时局部模型的残差被强制为零，无法表达内部弹性恢复；
   位移预测到瞬时速度的恒加速度解释也在快速卸载时有明显误差。
   因此本轮首先暴露的是**局部动力学 / 状态转移的缺口**，而非固定边界未生效或坐标符号错误。

**解释**：G 的部分误差接近 CV，主要伴随少触发门控；“少用当前尚不可靠的网络修正”
可以得到较低误差，但不等于几何更好。当前小数据、固定单种子、8 帧拟合网络不足以量化各模块的严格因果占比。

**下一轮只优先解决：局部状态转移中的自主弹性恢复与速度一致性。**
先固定 M 的当前几何 / 力条件，在现有中央数据中保留卸载和无接触片段，
验证能在无外部接触时产生恢复加速度、并按明确离散式更新位置和瞬时速度的局部模型。
接触分支继续作为外部驱动，内部恢复项不被接触门控关掉；训练和推理使用一致的几何候选口径。
这是一项后续改模任务，本轮未训练、未验证其效果，不同时搜索高斯表面或扩大数据。
只有该状态转移基线通过，三组接触条件的差异才更有解释价值。
