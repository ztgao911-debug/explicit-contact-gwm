# 软块 Gaussian 接触表面增密：CPU 几何验证

日期：**2026-10-27**。当前 Mac / CPU 已实际完成。
主结果：`outputs/contact_surface_validation/run_003/`。

**实测结论：稀疏表面空隙是原接触漏检的主要来源，增密显著改善覆盖，但尚未完全修好。**
左侧召回从 **7.65% 提升至 93.99%**；按压、保持均检出全部真接触帧，
释放仍漏检 11 帧，未达到预设 95% 召回线。
共同检出帧的部分接触点 / 法向指标退化，不能把增密称为全部几何精度改善。

本轮只验证接触几何，不训练、不重新标定、不计算代理接触力、不做状态 rollout。
已有神经网络干预响应失败的证据仍保留，不能由本轮覆盖改善推断已解决。

## 改了什么，目的是什么

仅新增独立的接触代理模块，原有动力学和接触管线保留。

| 项目 | 稀疏对照 | 增密代理 |
| --- | ---: | ---: |
| 动力学节点 | 140 | 140 |
| 固定动力学节点 | 35 | 35 |
| 表面碰撞 Gaussian 数 | 110 | 6914 |
| 原三角形每条边的细分数 | 1 | 8 |
| 静止网格坐标轴采样间距 | 10 mm | 1.25 mm |
| 静止子三角形最长边 | 14.142 mm | 1.768 mm |
| 球形压头半径 | 12 mm | 12 mm |
| 代理接触等值面半径 | 1 mm | 1 mm |
| Gaussian scale / 等值面倍数 | 5 mm / 0.2 | 5 mm / 0.2 |

沿用[修复计划](contact-surface-repair-plan.md)的保守 2 mm 尺度小试，
实现中将其明确定义为“**静止子三角形每条边不超过 2 mm**”。
原三角形含 14.142 mm 对角边，因此统一细分数为 `ceil(14.142/2)=8`。
这比“坐标轴间距 2 mm”的估算更密，不能混用两种定义。
本轮只运行这一种增密分辨率，没有密度或接触半径搜索。

利用已知**初始**表面三角拓扑，给每个代理固定三个父节点和重心权重。
共享边 / 顶点按节点编号与整数权重去重，代理编号固定；不是按当前空间距离重新合并。

```text
先将固定节点位置设为 rest、瞬时速度设为零
proxy_x(t) = Σ w_i * current_node_x_i(t)
proxy_v(t) = Σ w_i * current_node_v_i(t)
```

代理没有独立质量、运动自由度或监督目标。此处速度直接插值瞬时速度，
未用位移差除以 dt 代替瞬时速度；本轮不引入新的时间积分假设。
固定代理共有 1617 个，其位置和速度误差均为零。
2 mm 是静止绑定时的边长上限，不是任意形变下的保证；本批当前状态中
观测到的最大子三角形边为 **1.976 mm**，更强拉伸仍可能需要另行处理。

这是**有已知初始拓扑绑定的 Gaussian 碰撞代理**，不是无拓扑表面重建。
推理接口仅接受当前节点 x/v、当前球心 / 速度和球半径，
不读取当前 MuJoCo 表面、接触、力、未来状态或未来动作。
返回接触的 `object_indices` 是**代理编号**，不能直接当作原 140 个节点的编号。

当前两侧均为各向同性球，仍调用已有 `compute_gaussian_contacts`；
此时中心连线方法是准确的球间距。球形压头完整保留，不需要表面增密。
查询不设置候选数截断，避免密集代理被旧的上限默默裁掉。

## 实际评价协议

种子 7，CPU 单线程，模型更新 0。

1. 静止形状：110 个表面顶点、324 个边中点、216 个三角面重心，
   加一个原网格单元内固定偏移的 17×17 顶面网格，共 **939 个位置**。
   偏移 `(i+0.371)/17`，用于检查不与采样格点重合的位置。
   每处查询分离 0.5 / 0.05 mm，以及压入 0.05 / 0.1 / 0.5 / 1 mm，
   共 **5634 次 / 方法**。边缘、角点和底面均保留。
2. 每个位置的 MuJoCo 接触起始点用 16 次二分实际测量，区间宽约 **0.0763 μm**。
   代理起始点用球并集与运动球心直线的解析交点计算，并在前后各 0.1 μm 实际查询确认。
3. 中央浅 / 深、左侧浅 / 深、无接触对照五条轨迹，各取当前帧 0–299，
   共 **1500 帧 / 方法**，包含接近、按压、保持、释放和恢复。
   不筛掉无接触帧；不加载右侧数组，不用状态预测误差选择密度。
4. 检测主参照是从相同当前状态重建的 MuJoCo 原生碰撞几何，
   只调用 `mj_fwdPosition`，不调用真实力求解或积分。
   另用当前连续三角表面到球心的精确最近点距离作**仅评分**参照：
   `gap = distance - sphere_radius - skin_radius`，单位为米。
   球心位于材料表面外部；本轮不验证球心深入物体内部的有符号距离。

两方法使用完全相同位置、当前状态与评分区域。原生与连续网格的接触 / 分离判定，
在全部静态查询与轨迹查询中一致。连续网格距离函数不进入 Gaussian 预测。
原稀疏候选数在全部 1500 帧上复现上一轮机制审计。

最初 650 个特征点的检查包含与增密格点重合的位置，因此在完整运行 `run_002`
后补入固定偏移网格，在 `run_003` 完整重跑；代理参数和验收阈值均未调整。
这项补充改善检查覆盖，不是提高验证召回率的调参；两次的轨迹结果相同。

## 实测结果：距离、接触点与法向

左侧相同 **600 帧**的最小间隙 RMSE，相对连续当前网格，
从 **0.37246 mm** 降至 **0.00731 mm**；相同 **183 个真接触帧**为
**0.67441 → 0.01322 mm**。增密在全部左侧帧的最大间隙高估约 **29.66 μm**。
有限球采样仍低估连续面的覆盖，释放时很小的真实穿透会被判为正间隙。

以下是原生接触候选与预测候选的对称最近邻点误差 / 最近邻法向夹角，
先按帧求均值，再对帧平均。它衡量候选集合，受候选覆盖范围影响：

| 匹配帧口径 | 方法 | 帧数 | 接触点误差 mm | 法向误差 ° |
| --- | --- | ---: | ---: | ---: |
| 各自检出的左侧帧 | 稀疏 | 14 | 0.40425 | 1.72910 |
| 各自检出的左侧帧 | 增密 | 172 | 0.69737 | 3.85422 |
| **共同检出的相同左侧帧** | 稀疏 | 14 | 0.40425 | 1.72910 |
| **共同检出的相同左侧帧** | 增密 | 14 | **0.42260** | **2.25588** |

因此不仅不能直接比较 14 帧与 172 帧的条件均值，
在共同帧上也实际存在退化。小球并集的局部法向来自球心连线，
不会因增加采样点就自动等于连续材料面的法向；候选集合也不同于求解器的接触流形。
本轮没有更改法向估计或接触合并。这是独立于检测召回的剩余问题。
另存有相同真接触帧的最近代理 / 连续面代表点与法向指标，不把它与整候选集合混称。

## 实际开销、检查与失败

Mac Apple Silicon arm64，Python 3.13.5、Torch 2.14.1、NumPy 2.5.4、MuJoCo 3.3.7。
完整 `run_003` 主运行耗时 **51.57 s**，主运行输出约 **6.21 MB**（十进制，补充记录前）。
加入释放放大图、独立复核和最终源码 / 文档快照后约 **6.46 MB**。
单独的查询基准使用中央深压第 110 帧，预热 10 次、计时 200 次，CPU 单线程：

| 查询方法 | 中位耗时 ms | P95 ms |
| --- | ---: | ---: |
| MuJoCo 原生几何 | 0.493 | 0.565 |
| 稀疏 Gaussian | 0.480 | 0.561 |
| 增密 Gaussian | 2.138 | 2.250 |

Gaussian 计时包含当前状态插值、建云、接触查询与最近代理查询；
不包含连续网格评分、网络、力模型或状态更新，不能据此宣称完整模型实时。
代理数约增至 62.9 倍，这个场景中查询耗时约增至 4.46 倍；其他场景未验证。
左侧每帧候选数最大从 1 增至 35，不能直接把旧的每候选弹簧力复制过来求和。

已实际检查：

- 原 140 个节点编号与已有数据保留，代理只读当前输入；849 个既有数据 / 输出文件 SHA256 不变。
- 固定代理位置 / 速度误差为零，固定节点输入梯度为零，位置 / 速度输入不被修改。
- 预测接触量、21 个数值归档及代表状态梯度有限；不作全状态空间稳定性保证。
- 代理绑定保存重载后接触字段与间隙逐位一致。
- 后续帧和接触 / 力标签置 NaN，不影响当前查询；单测禁止 Gaussian 查询调用原生几何 / 力 / 积分。
- **现有及新增测试 122 项通过，Ruff 通过。**

独立 NumPy 实现重算全部 1500 帧 / 方法，间隙与保存表最大差约
**7.11e-15 mm**，候选数差异为零；原始接触归档与结果表的候选数也全部一致。
这些是保存与几何算术复核，不是额外训练或新增测试集成绩。

`run_001` 完成查询后，在汇总 JSON 保存时遇到 NumPy 布尔类型序列化错误。
已改为 Python 标量，故障与原输出保存在该目录；`run_002` 完整成功。
`run_003` 补充偏移网格与相同帧诊断后完整成功，无查询异常、非有限值或样本丢弃。
释放放大图和漏检表由 `run_003` 已保存数值补充生成，不改代理或预测；入口已包含这些输出。
首次局部单测另修正了测试输入先用 float32 再转 double 引入的精度误差。

预先设定的静态起始偏差 ≤0.1 mm、左侧无假阳性、固定 / 有限 / 重载检查通过；
**左侧召回 ≥95% 未通过，整体验收不能标为全部通过。**
本轮的严格零间隙判定不等于允许 0.1 mm 几何误差：微米级接触仍会影响二值召回。

## 解释与下一优先项

**实测支持：**在保持球形压头、皮肤厚度、原动力学节点不变时，
只补表面代理便消除了绝大多数漏检，并显著减小间隙误差。
这支持原来的表面采样空隙诊断。

**仍未验证：**新候选上的解析合力、力矩、密度收敛、冻结网络输入分布、
单步与 rollout 预测，以及接触干预响应是否改善。
当前既有 `PinnedContactPipeline` / `JointStatePipeline` 的默认行为保持原样，
不会将这份几何结果冒充整条预测管线已修复。

下一轮优先处理**临界接触的离散距离与法向一致性**，
用连续表面参照保持检查，明确有限采样误差和有效容差，避免仅追逐总体召回继续盲目增点。
临界几何口径明确后，再单独建立面积权重 / 接触聚合并检验密度变化下的合力，
决定是否接入局部网络；不能让采样数直接决定总力。
神经网络在真实几何 / 力条件下的错误干预响应仍是后续独立问题。

## 复现与产物

```bash
source .venv/bin/activate
python scripts/validate_contact_surface.py
python -m pytest
python -m ruff check .
```

入口自动选择新 `run_NNN`，拒绝覆盖已有目录；配置为
`configs/validate_contact_surface.yaml`，几何模块为 `src/contact_gwm/surface_proxies.py`。
需要已有 `pilot_001` 数据和项目 simulation / dev 依赖，不依赖历史训练权重。

输出包含配置、源代码快照、稳定代理绑定、样本名单、全部接触候选归档、
逐查询 / 逐轨迹 / 分阶段 / 分区域指标、接触事件、共同帧指标、曲线、
运行环境、时间 / 容量、检查、历史 SHA256 和故障记录。
这是一轮有已知状态和初始拓扑的几何验证，不是自由多步预测或跨位置泛化结论。
